# 《致爱丽丝·利德尔》哥特项目合集

> 产品规格与视觉技术蓝图 v1.1
> 文档状态：第一期已实现（墓地主场景 + 图书馆之梦）；AI 补写句仍待人工审定
> 项目类型：单人沉浸式前端展示 / 互动叙事展馆

## 1. 项目定义

### 1.1 命名关系

- **项目名**：**致爱丽丝·利德尔**
- **合集名**：**《玫瑰与灰烬》哥特式星座盘**
- **主场景**：**利德尔墓地**，所有子项目从这里进入
- **一句话定位**：一座献给爱丽丝·利德尔、也献给一切逝去之物的数字哥特纪念碑。

命名解释：

“玫瑰与灰烬”负责承载死亡、失去与纪念；“哥特式星座盘”负责承载观测、占卜与世界情绪。两者共同组成《致爱丽丝·利德尔》的叙事骨架，而不是八个彼此割裂的 Demo。

### 1.2 目标

1. 用一个可探索的墓地场景证明前端技术、动效与审美能力。
2. 让访客在 3–8 分钟内完成一次完整的“入墓地—探索—留下痕迹—离开”体验。
3. 每个子项目既可独立展示，也能被主场景的叙事串起来。
4. 首期不依赖账号系统与复杂后端，打开网页即可体验；需要公共内容时再接入轻量 API。

### 1.3 非目标

- 不做传统营销首页，不放大段功能说明或产品卡片墙。
- 不在 MVP 阶段实现真实新闻抓取、完整用户社区、支付、登录、后台 CMS。
- 不复刻《恶魔城》或《神之亵渎》的具体角色、素材或 UI；只借鉴其纵深、宗教感与暗黑氛围。

### 1.4 第一期开发表面

第一期只完成两个可用空间：

1. **利德尔墓地**：作为主页、导航中枢和完整的视觉演示场景。
2. **图书馆之梦**：作为第一个真正可停留、可交互的展馆。

其余七个展馆在墓地中保留入口轮廓或封闭门扉，点击后展示“尚未开放”的叙事状态，不提前实现半成品功能。这样首期可以把一张背景图、Canvas 前景、视差、音频和一套完整交互打磨到可发布质量。

## 2. 核心叙事

访客以“夜行者”的身份抵达利德尔墓地。墓园中央有一块写着“致爱丽丝·利德尔”的墓碑，周围分布钟楼、温室、圣堂、图书馆、星盘台等地点。这里的“利德尔墓地”是本项目的虚构叙事场景，承担“埋葬爱丽丝之处”的设定，不作为现实墓址说明。每一处地点对应一个小项目，是墓地记忆的不同容器：

- 玫瑰保存失去之物。
- 钟声保存此刻的祷告。
- 塔罗保存不确定的命运。
- 骨骼与纹章保存算法生成的个人痕迹。
- 圣像保存一次性的数字遗物。
- 图书馆保存声音与句子。
- 星盘把世界的情绪映射成可凝视的天体。

离开前，访客可以在墓碑前点燃一支蜡烛，看到本次访问生成的“墓志铭片段”。这段片段由本次交互产生的参数组合而来，不需要真实 AI，也不冒充心理诊断。

## 3. 页面与信息架构

### 3.1 首屏：利德尔墓地（Hub）

首屏即墓地，不设置独立 Landing Page。桌面端为 16:9 宽画布，移动端为纵向可拖拽画卷。

场景层级（由后至前）：

1. 深红至黑色天空、月蚀与缓慢移动的云层。
2. 远景尖塔、枯树和墓园围墙。
3. 中景钟楼、温室、图书馆窗户、圣堂拱门。
4. 前景墓碑、铁栅栏、玫瑰花瓣和烛火粒子。
5. HUD：项目题名、当前位置、静音/音量、返回墓地、访问记录。

所有地点都是可点击热点。热点使用图形与微弱呼吸光提示，不使用大面积说明文字。点击后打开对应“展厅”或全屏仪式层；按 `Esc`、返回按钮或移动端下滑可回到墓地。

### 3.2 展厅导航

- 左上：当前位置（例如“利德尔墓地 / 玫瑰温室”）。
- 右上：BGM、音效、减少动态、语言预留入口。
- 底部：当前展厅的极短句子与操作提示，仅在首次进入显示一次。
- 展厅之间可通过“黑色门廊”切换，但默认回到墓地，保持地理记忆。

### 3.3 第一期用户路径

```text
进入墓地（用户手势同时开启音频）
  -> 观察墓碑、钟楼、图书馆等可点击热点
  -> 点击「图书馆之梦」
  -> 点燃壁炉 / 点击窗户 / 翻开书籍
  -> 在图书馆停留或返回墓地
  -> 墓碑前显示本次访问的短句
```

- 主页不使用滚动卡片替代空间探索；点击任何可交互区域都要有视觉或声音反馈。
- 首次进入只提示一次操作方式，之后保持安静；用户可以随时打开帮助面板。
- 图书馆展厅以全屏场景承载交互，不嵌套在主页卡片内。

## 4. 子项目规格

### 4.1 《玫瑰与灰烬》数字挽歌馆

**情绪目标**：允许访客把失去的事物交给一个不会追问的容器。

- 输入：一句话，建议限制 80 个字；支持匿名提交。
- 生成参数：花瓣数量、卷曲度、下垂角、暗红/灰褐比例、茎的弯曲、粒子速度。
- 视觉：Canvas 绘制花瓣，中心花朵偏暗红，边缘逐渐灰褐；花瓣脱落后进入下方灰烬层。
- 交互：提交后 2–4 秒生成；悬停/触摸玫瑰时轻微颤动并显示匿名文字；支持“只保存本地”开关。
- 文案占位：`[在这里写下你失去的事物]`、`[它已被安放]`。
- 隐私：默认不收集姓名、邮箱、IP 展示；公共画廊需明确同意。

### 4.2 《钟楼回响》数字祷告室

**情绪目标**：用一次可控的声音与光波，把访客从浏览状态拉进仪式状态。

- 点击钟绳或按钮触发 Web Audio 合成的低沉钟声。
- Canvas 绘制暗金色同心波纹，持续约 3 秒；页面边缘出现一次呼吸式暗金光。
- 从约 100 条箴言中随机取一句；整点时只在访客停留页面时提示，不强制播放。
- 提供“敲响我的时区”按钮，时区通过浏览器 `Intl.DateTimeFormat` 获取。
- 文案占位：`[箴言库由作者提供]`。

### 4.3 《塔罗牌博物馆》交互式图鉴

**情绪目标**：把资料浏览变成一次小型占卜。

- 78 张牌分为大阿卡那与四组小阿卡那，支持筛选和键盘浏览。
- 点击卡牌触发 CSS 3D 翻转；背面显示牌名、正位牌义、逆位牌义、作者短句。
- “今日牌”使用日期作为本地种子，每个自然日稳定；不声称预测现实。
- MVP 卡面采用 SVG 几何构图，后续可替换为更复杂的 Canvas 插画。

### 4.4 《骨骼生长》算法生物

**情绪目标**：让算法本身成为一具不断死亡、不断再生的生物。

- 全屏 Canvas，递归分形生成脊柱、肋骨、枝蔓与刺状末端。
- 背景为深红到黑色的径向渐变，线条为灰白与少量暗金高光。
- 空格键或“再生”图标生成新种子；鼠标/触摸拖动改变旋转与倾斜。
- 需要提供帧率保护：低性能设备自动降低分支深度和粒子数量。

### 4.5 《乌鸦信使》生成式纹章

**情绪目标**：让访客带走一枚属于自己的黑暗家徽。

- 用户输入单词/名字，使用稳定哈希决定盾牌轮廓、中央符号、护盾兽、冠饰与缎带布局。
- Canvas 或 SVG 绘制，确保同一输入始终得到同一枚纹章。
- 支持 PNG 下载；下载图中包含项目名与生成日期，不包含未经同意的用户输入原文。
- 公共画廊为可选二期能力，需内容审核与删除机制。

### 4.6 《圣徒遗骨》像素圣像画

**情绪目标**：把一次生成结果当作短暂、可保存的数字遗物。

- 使用 32×48 或 48×72 的逻辑像素网格，再按整数倍放大显示，避免模糊。
- 随机决定头部倾角、眼睛颜色（暗金/血红/灰白）、光环形态、裂纹与雨丝纹理。
- 支持重新生成、锁定部分参数、保存 PNG。
- 文案占位：`[圣徒名]`、`[遗骨编号]`。

### 4.7 《图书馆之梦》环境音交互页

**情绪目标**：提供一个可以停留的背景空间，而非一次性点击玩具。

- 场景由 CSS/SVG 分层绘制：窗、雨线、壁炉、书架、桌面、尘埃。
- 第一版构图采用黄金比例：窗体宽度约占阅览室画布的 `61.8%`，书架与书桌后退为较小的中近景；窗内再叠加月色、星点、带拱窗与侧尖塔的远端建筑、带瓦线/老虎窗/烟囱的近端屋脊、枯树枝和雾层，保持多层纵深。室内再拆为后墙拱券/壁柱、墙面中景、家具中景和地板前景，镜头偏移量递增，避免所有物件共面。镜头支持左右延展，主房间外另设侧廊与画像墙。
- 远景视差不只靠透明度：窗外背景、远端建筑、近端屋脊和枯枝按不同层级绘制并随横向镜头偏移；拖拽、滚轮和左右方向键均可平移，范围受边界约束，室内热点随镜头同步移动。所有尖塔底部必须落在连续的远景街墙/地平线上，不允许悬空断裂。
- 右侧画像使用 `local_docs/image.png` 作为私人参考源，运行时先追踪画布边缘连通的白底区域并保留人物内部白色肤色/衣物，再暖色压缩高光，叠加拱形画框、布面交叉笔触、金属铆钉和铭牌；原始头像不直接作为白底图片铺入场景。
- 室内墙面、书架、壁炉和桌面使用不透明底色与材质描线；熄火态维持冷暗环境，点火态必须增加暖色照明、石材反光和火焰光晕，不能只改变火焰形状。左侧侧廊配置石质雕像与控制台，中央配置阅读椅，右侧画像墙配置立式复古灯与小桌；地板使用横向木纹、错开的短竖板缝和透视辐射线，左右侧廊不额外压暗。
- 点击壁炉提高火焰粒子和低频噪声；点击窗户增强雨声；点击书籍随机翻页并显示一句诗；点击画像从画像文案池随机弹句；左侧哥特门点击显示“不知为何握不住门把手”。
- 音频采用 Web Audio 节点合成或短音效文件；每一层可独立静音。
- 提供“专注模式”：隐藏 HUD，仅保留场景、音量与退出按钮。

**第一期实现边界**：先做一间可停留的主阅览室，不扩展地下书库、角色对话或藏书管理。场景中固定 5 个热点：壁炉、窗户、一本桌面孤本、右侧画像和左侧哥特门。每个热点都要有默认态、激活态、再次点击的可逆态，以及音效不可用时的静默回退。

首期停留体验的目标时长为 2–5 分钟：访客可以只听雨，也可以依次触发火焰、雨声和翻页，最后得到一条来自书页的短句。短句不强迫用户继续点击，允许把图书馆当作背景页面使用。

### 4.8 《哥特式星座盘》

**情绪目标**：把世界的情绪变成一张不可靠但迷人的占卜图。

- 中世纪天球仪构图，星点、连线、黄道环与刻度均可旋转。
- 星点颜色：负面为暗红，平静为银灰，正面为暗金；亮度映射情绪强度。
- MVP 使用本地预置数据，星点说明写成“样本情绪”，避免制造新闻事实感。
- 情绪数据固定来自本地预置样本，不接入新闻抓取、外部来源链接或 NLP 接口。
- 该展厅是合集的视觉收束点：离开时星盘中央显示本次访问生成的“今日星尘”。

## 5. 视觉系统

### 5.1 方向关键词

恶魔城式哥特建筑、神之亵渎式宗教器物感、90 年代日本动画的硬朗轮廓与有限赛璐璐阴影。目标是“可读、可操作的展馆”，不是堆叠装饰。

### 5.2 色彩

| 用途 | 色值建议 |
| --- | --- |
| 墨黑背景 | `#09090b` |
| 深红主调 | `#3a1018` |
| 血红强调 | `#8f2834` |
| 灰烬文本 | `#b8b1ab` |
| 骨白高光 | `#e5ded2` |
| 暗金交互 | `#a98245` |
| 危险/错误 | `#c44747` |

避免全页面只使用单一蓝紫或棕色；红、灰、骨白、暗金应有明确功能分工。

### 5.3 字体与排版

- 标题：高对比哥特/古典衬线字体；必须准备系统回退字体。
- 正文：清晰的中文宋体或现代黑体回退，保证长文阅读。
- 标题不超过两行；按钮文案短而明确；不把操作说明做成装饰性长段落。
- 所有字距保持默认或正值，禁止负字距压缩中文。

### 5.4 动效原则

- 多层纵深：背景云、建筑、前景粒子以不同速度响应指针/陀螺仪。
- 动效以缓慢、克制、可中断为主；仪式动效有明确开始与结束。
- 支持 `prefers-reduced-motion`：关闭视差、粒子与 3D 翻转，保留状态变化。
- 不使用无目的的渐变球、漂浮光团或卡片套卡片布局。

### 5.6 Canvas 素材质量与迭代规则

Canvas 不是“几条线加几个粒子”的占位图。凡是作为主视觉被用户看到的绘制素材，至少要具备轮廓、材质、光影和运动中的两项差异。首期墓地与图书馆的最低门槛如下：

- **分层**：背景、主体、前景至少三层，层间有不同的视差或雾化速度。
- **材质**：石材、玻璃、木材、雨水、火焰等重要物件必须有可辨识的纹理变化，不能只用纯色填充。
- **细节密度**：桌面、窗框、墓碑等近景物件要有边缘高光、破损/污渍或重复纹理中的随机扰动；像素元素只作为局部材质笔触，不得把完整轮廓降为马赛克。
- **动态**：每个展厅至少有两种独立动态系统（例如雨线 + 火焰，雾气 + 烛光），并可单独暂停。
- **可复现**：随机生成使用显式 seed；稳定的生成结果保留 seed、参数和截图，方便转为本地素材。
- **降级**：提供低粒子、低分支、关闭视差三档，任何降级都不改变信息层级。

建议的多轮固化流程：

1. 轮次 A：只做黑白构图，确认热点位置与前中后景比例。
2. 轮次 B：加入材质纹理与有限色板，检查缩放和移动端裁切；保留平滑线稿。
3. 轮次 C：加入光影、雨雾、火焰等动态，记录帧率和内存。
4. 轮次 D：至少生成三组不同 seed，排查重复纹理、穿帮和过度闪烁。
5. 轮次 E：把稳定版本导出为 `public/assets/` 下的本地 PNG/WebP 或 JSON 参数；源代码仍保留，便于后续再次生成。

验收标准：100% 缩放下主体边缘清晰；200% 检查时没有明显的重复贴片；桌面端保持 60 FPS、移动端降级后保持 30 FPS；`prefers-reduced-motion` 开启时仍能看到静态构图和交互结果。

## 6. 音频策略

全局 BGM 候选：**《Es Ist Ein Schnee Gefallen》**。上线前必须确认录音版本的版权、来源与许可，优先使用可商用或作者自有录音。

- 首次进入不强制自动播放；显示一个明确的“进入墓地 / 开启声音”动作。
- BGM、钟声、雨声、壁炉声分开控制；默认音量低，支持记忆用户选择。
- 浏览器不允许播放时，界面仍完整可用，提示仅在需要时出现。
- 页面离开或切换展厅时使用淡出/淡入，避免声音叠加。

## 7. 技术方案

### 7.1 推荐栈

- 构建：Vite + TypeScript。
- UI：React（组件化管理展厅与状态）；样式使用 CSS Modules 或普通 CSS，避免过早引入大型设计系统。
- 绘制：Canvas 2D 为主，SVG 用于可缩放的牌面、纹章与建筑线稿。
- 动效：CSS transitions/animations；只有在确有必要时引入轻量动画库。
- 音频：Web Audio API。
- 状态：React Context 或轻量 store；MVP 不引入服务端状态管理。
- 部署：静态托管（Vercel、Netlify 或 GitHub Pages 均可）。

### 7.2 路由与状态

建议使用 hash 路由，保证静态托管直接刷新可用：

```text
#/cemetery
#/rose-ash
#/bell-tower
#/tarot
#/bone-growth
#/raven-heraldry
#/saint-relic
#/rain-library
#/gothic-orbit
#/winter-bell
```

全局状态至少包含：当前地点、BGM/音效音量、减少动态开关、访问过的展厅、今日塔罗牌、当前会话生成参数。

### 7.3 数据边界

MVP 数据全部随前端发布：

```ts
type RoseMemory = {
  id: string;
  text: string;
  seed: number;
  petalCurl: number;
  tone: number;
  createdAt: string;
  consentToGallery: boolean;
};

type Maxim = { id: string; text: string };

type TarotCard = {
  id: string;
  name: string;
  arcana: 'major' | 'minor';
  upright: string;
  reversed: string;
  line: string;
};
```

二期后端可使用 Supabase/Firebase 等托管服务，仅保存：生成参数、匿名文本、同意标记、创建时间、删除令牌。禁止保存不必要的身份信息。

### 7.4 性能目标

- 首屏静态资源压缩后目标小于 3 MB（不含可选音频）。
- 中端桌面设备 60 FPS；移动端在粒子降级后保持 30 FPS 以上。
- Canvas 依据 `devicePixelRatio` 设置上限，避免 4K 屏内存暴涨。
- 所有展厅按需初始化，离开展厅后暂停动画循环与音频节点。

## 8. 无障碍与可用性

- 所有热点同时提供可聚焦的键盘入口与可见焦点样式。
- Canvas 旁提供文本化操作入口和状态描述；不能把信息只放在画布像素中。
- 对比度满足 WCAG AA；不以颜色作为唯一反馈。
- 键盘操作：`Tab` 导航、`Enter/Space` 激活、`Esc` 返回、方向键浏览塔罗牌。
- 移动端触控目标不小于 44×44 px；横屏/竖屏均有明确布局。
- 输入内容限制长度并在本地提交前明确展示保存范围。

## 9. 文案系统

文案采用“短句、留白、具体意象”的虚无主义哥特风格，避免解释过度。每个展厅需要：

1. 一句入口题词（不超过 28 个中文字符）。
2. 一句操作反馈（不超过 20 个中文字符）。
3. 一段展开说明（80–160 字，可选）。
4. 空状态、错误状态、返回状态各一句。
